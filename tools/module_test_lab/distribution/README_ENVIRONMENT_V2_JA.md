# CanSat Simulation：Python環境管理（Updater v2 第2段階・開発版）

## 目的

機能追加で必要なPythonライブラリが変わっても、使用中の `~/cansat_gui_venv` を変更せず、リリースごとに検証済みの実行環境を使用するための仕組みです。

- 安定版に `requirements-runtime.txt` が存在する場合だけ、新しい独立環境を準備します。
- 同じPythonバージョン・依存関係の場合は保存済みの環境を再利用します。
- 配布前にファイル一覧のSHA-256検証とPythonの構文チェックを行う既存機構を維持します。
- インストール後に指定バージョン、`pip check`、PySide6の読み込みを確認します。
- 新しい実行環境の準備に失敗したら、GUIのバージョンを切り替えず、既存版を使います。依存関係を満たす旧GUIがない場合は起動を中止します。
- 以前のリリース（`requirements-runtime.txt`がないもの）は従来どおり、登録されているPythonを使います。
- v2クライアントの自己更新やGUIのロールバック機能を維持します。

## ファイル

- `tools/module_test_lab/requirements-runtime.txt`：通常のGUIに必要なライブラリ。現状は `PySide6==6.12.0` のみ。
- `tools/module_test_lab/requirements-test.txt`：開発者向けテスト環境。**班員の通常起動時にはインストールしません**。
- `~/.local/share/cansat-lab/environments/<ID>/`：新しい実行環境を隔離して保管。
- `~/.local/share/cansat-lab/environments/<ID>/ready.json`：検査に成功した環境だけにつく完了印。

## 依存関係の書き方

リリース時に読み込む `requirements-runtime.txt` では、1行につき `ライブラリ名==正確なバージョン` の形式だけを使用します。URL、`-r`、`--index-url`、実行オプション、可変のバージョン範囲は使用できません。PySide6は必須です。

例：

```text
PySide6==6.12.0
```

**注意**：直接指定するパッケージは固定されていますが、すべての依存ライブラリのダウンロードファイルをハッシュで固定する仕組みはまだありません。PyPIから取得するパッケージが含まれるため、安定版ブランチの保護とコードレビューを必須にしてください。

## リリース前に必ず行うこと

1. 隔離したPCまたは一時環境で、新しい依存関係のインストールとアプリ起動を確認する。
2. `test_updater_v2.py`、`test_updater_environment_v2.py`、全体の回帰テストを実行する。
3. これまでの旧環境に戻る手段を確認する。
4. 承認された変更だけを安定版へ反映する。現在は開発ブランチだけで作業し、`cansat-lab-stable` は変更しない。

## 開発中の試験

通常のPCにインストールしないこと。`publish_release.snapshot()` で一時フォルダに配布版を作り、`cansat_update.prepare_runtime_python()` を一時のクライアントフォルダに対して実行します。`requirements-runtime.txt` を変更しても、同一の環境は再利用され、新しい構成は別の環境に作られます。

## 更新に失敗した場合

新しい依存関係の取得に失敗したときは、既存の正常なGUIを継続します。その処理で新規作成した未完成のフォルダだけを破棄し、次の起動時に再試行できます。電源断などで途中終了した場合は `environments/<ID>/` が残ることがあるため、安全のため自動削除をせずに停止します。**対象IDと保存場所を確認してから**、開発担当が原因を調査してください。

この段階で、Gazebo・ROS 2・PlatformIO本体のインストールは行いません。コードのビルドも実行しません。
