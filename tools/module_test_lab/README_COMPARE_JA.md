# CanSat Module Test Lab v6 — C++コード比較・失敗原因分析

## v5から追加される機能

- 新しいGUIタブ **「着地コード比較」**（v5の「着地一括テスト」はそのまま使用可能）。
- **旧C++ / 新C++** をそれぞれ選択し、v5で用意した同一の8種類の仮想CSVで比較。
- 条件別に「改善」「悪化」「同判定」「比較対象外」を表示。
- 接地ラベル・検知時刻・遅延・データ欠損等の**CSVに記録された事実**と、**確認すべき仮説**を分けて説明。
- 旧コードと新コードを別々のグラフで確認（センサー時系列、着地と検知の縦線）。
- 結果のCSV出力、実験台帳への比較レポート1件の保存（GitHubへ自動送信しない）。
- バックグラウンドスレッドで比較（実行中もGUIの他タブを操作できる）。

## 試す手順

1. v6導入後、アプリを起動する。
2. **「着地コード比較」** タブを開く。
3. 初期状態では旧コード `cpp_landing/example_detector.cpp`、新コード `cpp_landing/example_detector_v2.cpp` が設定済み。
4. **「▶ 2コードを8条件で比較」** を押す。
5. 条件を選ぶと下部に旧／新の診断が表示される。グラフもそれぞれ切り替えられる。
6. 結果を **比較CSV** に出力するか、**比較レポート1件** を実験記録へ保存できる。

## 「改善」と判定する基準

- 旧：失敗、新：成功 → **改善**
- 旧：成功、新：失敗 → **悪化**
- 両方とも成功、または両方とも失敗 → **同判定**
- 少なくとも一方が未判定／入力エラー／実行エラー → **比較対象外**

**注意:**「改善」はこの8つの仮想条件における判定で、実機でより安全・高性能という意味ではありません。
新旧とも合格なら、遅延差 (新−旧、秒) で速度変化を確認できます。「同判定」が同一挙動を意味するわけではありません。

## サンプル新コードの限界

`example_detector_v2.cpp` は**教育用の比較サンプル**です。v5合成CSVの「着地後に気圧が完全に平坦になる」という人工的な特徴を利用しています。現実の気象や動作環境ではこの特徴が成立するとは限らず、**実機用アルゴリズムとしての妥当性はありません**。実際に使うC++コードでは、ハード依存部分から着地検知の純粋なロジックを分離し、既存 `landing_api.h` に合わせてください。

## 失敗原因の説明について

- **観測事実:** CSVに記録された接地ラベル、判定時刻、検知イベント、Z加速度の値など。
- **確認点（仮説）:** 閾値、判定継続時間、圧力変化、入力欠損など。
- C++の内部変数や分岐は本機能では記録していません。特定の行を「原因」と断定しません。
- `invalid_imu` は意図的に不正な入力です。C++自体の不良としてカウントしません。
- `no_truth` は正解ラベルがないため、合否比較に算入しません。

## 詳細・制約

- 使用するC++ソースは**信頼できるローカルの.cppのみ**。ホストPC上でコンパイルし、実行されます。
- 既存Pythonの`cpp_landing_runner.py`に従い、g++が必要です。Arduino SDK / ESP32本体は実行しません。
- コンパイル不能のコードがある場合、比較不能エラーを示します。
- 既存v1～v5、ROS 2、実機の記録、GitHubはインストーラーによって自動変更しません。
- 保存する比較レポートの台帳上のステータスは「未判定」です（単一試験の成功・失敗ではないため）。
