# v14: C++実コード・ホスト検証（ESP32-S3向け設計のうちPC可搬部分）

## 概要

v13.5のGUIと日本語入力、`cansat-lab`起動方法を維持したまま、ホーム画面に「Main・CAM・Drive C++実コード検証」を追加しました。Arduino IDEで利用している判断ロジックを、マイコン依存コードから分離した場合に、その**同じ共有C++関数**をPC側から試験できます。

**重要:** `.ino` をそのままコンパイルする機能ではありません。ESP32-S3のGPIO、センサー、カメラ、CAN、割り込み、タイミング、モーター実機、電源系の検証はできません。ホスト試験成功は安全・実機動作の保証ではありません。信頼できるC++だけを実行してください。PC上でコードをネイティブ実行し、OS sandboxはありません。

## 使い方

1. `cansat-lab` で起動し、「Main・CAM・Drive C++実コード検証」を開きます。
2. まずデフォルトのサンプルC++・CSVを選択した状態で、注意事項に同意して「ホスト試験を実行」を押します。10/10件PASSが期待されます（**デモ**であって本番コードの試験ではありません）。
3. チームメンバーの実コードで試す場合は、実機依存部分を除いた**共有ヘッダーの判定関数**を用意し、下記のC++アダプターから読み込みます。アダプターの配置先から参照可能なヘッダーを利用してください。
4. ケースCSVは `case_id,module,command,landed,expected` です。モジュール1=Main / 2=CAM / 3=Drive、コマンド1=着地 / 2=移動 / 3=撮影 / 4=停止、着地0/1、期待値 `1=許可, 0=拒否, -1=非対応`。
5. 試験完了後、期待値と実際値の比較結果をCSVまたはJSONで保存できます（自動アップロードや実験台帳への登録はしません）。ソース、試験条件、コンパイラが報告した依存ファイルのSHA256を結果に含めます。

## C++アダプターの仕様

現在のv10と同じ契約なので、チームが既存のv10アダプターを書いていれば流用可能です。

```cpp
#include "controller_contract.h"
#include "your_portable_policy.h"   // ここは実際の共有ロジックのヘッダーに置換
extern "C" int cansat_allow_command(int module, int command, int landed) {
    return your_portable_policy(module, command, landed);
}
```

`your_portable_policy` は擬似名です。実際に作成した関数名に置き換えてください。サンプルは `v14_host_examples/example_adapter.cpp` と `portable_decision.h` です。実機用 `.ino` でも同じヘッダーを利用すれば、PC側でテストした判断部分と実機の判断部分の二重実装を減らせます。ただし、ESP32固有ライブラリを共有ヘッダーに入れるとPC側でコンパイルできないことがあります。

**コンパイル実行は明示的な同意操作後のみ。** 実行にはUbuntuの `g++` が必要です。1回の試験で最大400ケース、コンパイルタイムアウト25秒、実行タイムアウト5秒です。複雑な計算や無限ループのあるコードでは異常終了することがあります。

## 既知の制約

- 制御判断の契約は `int cansat_allow_command(int module, int command, int landed)` のみ。今後IMU実数値、緯度経度、角速度、状態遷移などの入力は別の契約・データ形式が必要です。
- 大量の出力や不正なネイティブコードをOS sandboxで隔離しません。ユーザーが信頼できないC++を指定しないでください。
- 依存ファイルの一覧はg++ `-MMD` に基づくベストエフォートです。実行時に読み込まれる外部ファイルや動的ライブラリまではハッシュしません。
- 他のMain・CAM・Drive仮想CAN画面との直接自動同期、GitHubへのアップロード、実機書込みは行いません。
- 既存のv13.5実験・解析・GUI・入力設定・ランチャーは変更しません。
