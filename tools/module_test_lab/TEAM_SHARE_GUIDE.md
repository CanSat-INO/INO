# チーム向け：個別実験結果の共有ルール（初版）

## 担当者が実験したとき

1. 実験した**機能名**を選ぶ（着地検知 / GNSS・姿勢 / モーター制御 / 分離 / クローラー展開 / 通信 / カメラ・経路探索など）。
2. **実験者、コード版、試験ケース**を入力する。`landing_v03` や Git のコミットIDなど、再現できる識別子が望ましい。
3. **期待した動作**と**実際に見られた動作**を別々に記入し、成功 / 失敗 / 未判定を付ける。
4. ログ（CSV / TXT / LOG / JSON）を添付する。データを共有してよいか確認する。
5. 共有したい結果を選び、**「選択結果を共有ZIPに出力」**してチームへ送る。

## 集約担当者

1. 全員から共有ZIPを受け取る。
2. **「共有ZIPを取り込む」**を繰り返す。
3. 同じ実験IDは自動的に重複排除。**同じIDで内容が異なる場合は上書きしない**ので、担当者に確認する。
4. **「CSVで全結果を出力」**して一覧化する。
5. 定期的に `~/cansat_module_lab_data/` をバックアップする。

## 着地検知向け推奨ログ形式

Arduino担当者と、まずこの4列を共通ルールとして合意してください。

| 列名 | 単位 | 内容 |
|---|---|---|
| `time_ms` | ms | 計測開始からの経過時間 |
| `imu_z_mps2` | m/s² | 加速度Z（測定座標系を明記） |
| `pressure_pa` | Pa | BME280気圧 |
| `landing_detected` | 0/1 | ESP32-S3の判定結果 |

時刻同期の方法、IMUの加速度が重力を含むか、センサーデータの欠損値の表現なども決める必要があります。**このソフトの参考シナリオと実機ログの意味を混ぜないでください。**

## 現段階での限界

- `.ino` を直接実行しない。
- シリアルポートからの自動取り込みやArduinoプログラムの自動判定は未実装。
- ログの添付と記録の判定は手動。
- 自動クラウド同期なし。共有ZIPはチャット・Drive等で各担当者が送る。
- こちらの初版で仮想センサーデータを生成するのは着地検知モジュールのみ。その他は実験記録・共有を先に用意。
