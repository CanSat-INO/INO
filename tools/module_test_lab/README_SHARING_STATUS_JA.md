# 共有先の接続確認と、画面共通の保存・共有状態

## 接続を確認する

1. プロジェクトのホームで自動共有をOFFにし、通信が終わってから「共有設定」を開きます。
2. 班のGitHubリポジトリURLを貼り「接続・権限を確認（送信しません）」を押します。
3. 参照できるか、書込み権限があるとGitHubが報告しているかを確認できます。ブランチ・年度・班は詳細設定で変更します。
4. 設定を保存してから、自動共有を使う場合に限りホームで送信先・対象を確認してONにします。

接続確認は参照のGETだけを使用し、テストファイルや実験データを送信しません。確認ボタンを押しただけでは設定保存や自動共有の有効化も行いません。
書込み権限の情報がない場合は不明と表示します。権限があると報告されても、保護ルールで実際の書込みが制限される場合があります。
接続未確認でも設定を保存できます。通信できない場所でもPC内で作業を続けられます。設定保存後の自動共有はOFFです。
ZIPの保存先は任意で、軽い記録だけなら未設定で始められます。各PCのローカルフォルダーが自動的に同期される機能は追加していません。

ログイン不足、権限、共有先やブランチ、通信制限、ネットワークなど、確認する場所を表示します。
通信制限の待機中に確認ボタンを押しても、待機時間が過ぎるまで再通信しません。接続確認中に閉じる場合は通信停止を待って閉じます。

## 各機能画面で状態を見る

選択中のプロジェクトの画面下部に、PC内の保存件数とGitHubへの共有状態を表示します。
「保存・共有の状態…」を押すと、共有先・台帳保存先・ZIPの設定・件数・最終確認・対処方法を開けます。
状態確認のために作業画面を移動する必要はありません。必要なら詳細からホームや共有設定へ進めます。
実験ワークスペースでは下書きと結果、記録票ではその入力の保存状態も表示します。

| 状態 | 意味 |
|---|---|
| PC保存 N件 | 選択したプロジェクトの台帳にある件数 |
| 自動共有OFF | 自動送受信を有効にしていない。手動共有の有無とは別 |
| 共有状態は未確認 | この起動ではまだ記録の照合結果がない |
| 共有待ち・未確認 | 新しい記録や、この起動で未照合の記録がある |
| 共有確認済み | 現在の記録内容と同じ内容を、この起動中にGitHub上で確認した |
| 要確認 | 同一IDの競合、添付やZIP設定などの確認が必要 |
| 接続待ち・要確認 | 通信・ログイン・権限等の問題。PC内の保存は継続できる |

再起動直後に過去の送信を推測して「共有済み」とは表示しません。照合結果はこの起動中の確認です。
手動送信した記録も、自動共有の照合が済むまでは未確認として扱います。空の台帳は「共有確認済み」とは表示しません。
記録内容が変更されれば以前の確認は一致しなくなり、削除した記録は件数に含めません。
ZIP本体が別PCへ到着したか、展開したかは、このGitHubの件数には含みません。ZIP一覧で別途確認してください。
台帳を読めない場合は、以前の成功表示を残さず未確認と表示します。

状態表示のための新しいネットワークポーリングはありません。保存・更新・既存の同期イベントで再計算します。
文字入力中は保存件数の計算結果を利用し、入力のたびに台帳全体を読み直しません。
未分類の従来台帳と、プロジェクト未選択のトップ画面には、このプロジェクト専用表示を付けません。

## 維持した操作

既存の4入口、直接操作ボタン、下書きと実験結果の保存形式、Git/ZIPの保存先は維持します。
自動共有ON時の対象確認、非公開リポジトリの確認、同じIDの上書き拒否、通信制限時の待機も維持します。
今回の確認で新しいサービス登録、課金、GitHubのメンバー権限変更、リポジトリやブランチの作成は行いません。
