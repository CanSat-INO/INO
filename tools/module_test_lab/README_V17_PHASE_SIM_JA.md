# CanSat Module Test Lab v17 — フェーズ別ミッション・仮想試験

## 目的

コード担当がESP32-S3のブレッドボード実験、個別コード、フェーズ別コード、
メインコードの順で開発する間に、状態遷移の条件・例外処理・ログ形式を**仮想データで確認**します。
ROS 2/Gazeboによる統合シミュレーター、実機地上局、および本番Arduinoコードとは独立です。

## この画面でできること

- `ミッション通し`、`着地判定のみ`、`GNSS測位のみ`、`GPS誘導のみ`、`カメラ誘導のみ` の選択。
- 正常、着地判定不成立、GNSSタイムアウト、目標未検出、障害物、緊急停止の模擬ケース。
- 着地加速度・角速度・安定時間、測位待ち時間、仮想距離・仮想速度、目標検出時間などの編集。
- フェーズ切替タイムライン、仮想距離推移、時系列表、遷移時刻・停止理由の可視化。
- CSV（UTF-8 BOM付き）とJSON（実行条件、入力SHA256、遷移、全行）の保存。

## 重要な制限

**ミッション再現の教材用・制御ロジック設計用の単純化モデルです。**

- 実機の慣性運動、落下力学、風、車輪と土壌の力学、GNSS誤差、カメラの画素処理、センサー故障率はモデル化しません。
- `着地判定 >=15m/s²、角速度 <=5°/s、安定時間 >=600ms` などの閾値は、この画面の**デモ仕様**であって実機推奨値ではありません。
- GPS誘導では距離を固定の仮想速度で減らすだけで、座標・方位・障害物回避は計算しません。
- カメラ認識と赤色比率は距離から作る仮想値であり、画像検出エンジンではありません。
- `PASS` はデモの条件が成立したことだけを示します。実機の成功・安全性を保証しません。
- `.ino` を実行、ESP32-S3と通信、ROS 2と通信、ファイル読込、結果の自動送信は行いません。

## 使い方

1. `cansat-lab` で起動します。
2. ホームで「フェーズ別ミッション・仮想試験」を開きます。
3. `ミッション通し` × `正常ケース（仮想）` を選んで「仮想試験を実行」を押します。
4. 状態遷移・仮想距離・時系列表を確認します。
5. 必要なら条件を変えて再実行し、CSV / JSONを手動保存します。

## 想定結果（デフォルト）

| モード / ケース | 期待 |
| --- | --- |
| ミッション通し / 正常 | PASS。着地→GNSS→GPS→CAM探索→CAM接近→完了 |
| ミッション通し / 着地不成立 | 着地待機→停止 |
| ミッション通し / GNSSタイムアウト | GNSS待機で停止 |
| ミッション通し / 目標未検出 | CAM探索で停止 |
| ミッション通し / 障害物 | GPS誘導で停止 |
| ミッション通し / 緊急停止 | 停止 |

## テスト・バックアップ

`python3 -m unittest discover -s tools/module_test_lab/tests -p 'test_v17_phase_core.py' -v`

インストーラーは既存 `app.py` のSHA256を検査して変更を保護します。
リポジトリ外 `~/cansat_v17_backups/` に更新前のファイルとマニフェストを保存します。
