# CanSat Simulation：GitHubと共有フォルダー

年度・班でプロジェクトを分け、小さい実験記録をGitHub、重い資料を指定フォルダーのZIPで共有します。
新しい有料サービス、データベース、Git LFS、Gazeboなどはインストールしません。
共有フォルダーがなくても、PC内の保存と軽い記録の共有から始められます。

## 最初の設定

1. ホストはトップで名前・年度・班・担当者・目的を入力し、プロジェクトを作ります。
2. ホームの「共有設定（年度・班／GitHub／ZIPの場所）…」を開きます。
3. データを置く非公開GitHubリポジトリを `owner/repository` またはURLで指定します。ブランチは既存のものを指定します。リポジトリ・ブランチは自動作成しません。
4. ZIPの場所は未設定で構いません。使える共有フォルダーができたら、各PCでその場所を選びます。
5. ホームの「このプロジェクトをGitHubと自動共有」をONにし、送信先と対象を確認します。初期状態はOFFです。設定を変更するとOFFに戻るので再確認してください。
6. メンバーはトップの「班のプロジェクトに参加」で同じリポジトリのリンクを入力し「プロジェクトを探す」。一覧から同じIDのプロジェクトへ参加します。ブランチが main 以外なら詳細設定で指定します。
7. メンバーもホームの共有設定で、このPCからZIPを開ける場所を指定します。共有ファイルによるプロジェクト登録も引き続き利用できます。

たとえばホストの `/mnt/d/cansat-share` と、メンバーの `/home/member/team-share` に**同じ内容**が届く仕組みが必要です。
各PCの好きな空フォルダーを指定しただけでは共有されません。今回の更新はフォルダー間の転送・同期サービスを追加しません。
NAS・大学の共有ドライブ・既存の同期フォルダー・手動コピー等で、後から同じ内容を利用できます。
絶対パスはそのPCの設定だけに保存し、GitHubやプロジェクト共有ファイルには入れません。

同じリポジトリに複数年度・複数班を置くことも、班ごとに別リポジトリを使うこともできます。
年度・班の変更は表示上の整理で、IDや台帳を変更しません。翌年度の実験を分けるときは新規プロジェクトを作ります。
同名を作っても同じプロジェクトにはなりません。同じIDを共有して参加します。
アプリでメンバーを指名・承認する機能はありません。データの閲覧権限はGitHubリポジトリと共有フォルダー側で管理します。

## 保存の分担

| 内容 | 保存先と動作 |
|---|---|
| 名前・年度・班・実験条件・結果 | 各PCのJSON台帳。自動共有ONのときGitHubにも保存 |
| 1個900KB以下の添付 | GitHubで送受信。各PCの添付に保存 |
| 900KBを超える保存済み添付 | 共有先にZIPを作り、GitHubにはZIPの照合情報だけ保存。元の記録と添付は変更しない |
| 大きいモデル・Gazebo資料・10MiBを超えるログ | ホーム「ファイルをZIP登録…」「モデルフォルダーをZIP登録…」から登録 |
| 受信したZIPの本体 | 自動展開しない。「選択ZIPを検証して開く」で必要な資料だけ利用 |

GitHubの保存先は互換性のため `<選択リポジトリ>/<選択ブランチ>/data/ino/projects/<ID>/` です。
`ino` という既存の内部フォルダー名でも、別の班のリポジトリを選択できます。別IDの記録は混ぜません。
GUIの配布元 `CanSat-INO/INO` の `cansat-lab-stable` とは別設定です。
GUIの更新は開発用 `~/INO-module-lab` や他メンバーのファームウェアを変更しません。

## ZIPの使い方

1. 資料名を付けて登録し、元の件数・サイズ・ZIP保存先を確認します。登録時に指定先の容量を使います。元ファイルは残ります。
2. ZIPは `cansat-projects/<プロジェクトID>/packages/<記録ID>/<一覧ハッシュ>/bundle.zip` に保存します。
3. GitHubには相対パス・サイズ・SHA256・記録との関係を保存します。新しい版は新しい記録として登録します。
4. 受信PCで場所が未設定・未到着なら「ファイル待ち」です。共有フォルダーの内容が届いた後に「一覧を更新」します。
5. 「選択ZIPを検証して開く」はZIP全体と内部ファイルのSHA256・サイズ・IDを検証します。破損したZIPは開きません。モデルは必要な作業場所へ自分で展開します。
6. 自動共有で受け取った大きな実験添付は「選択ZIPの添付をこのPCへ復元」を押すと、検証後に元の添付場所へ追加します。既存の異なるファイルは上書きしません。復元後に従来の解析機能で利用できます。

ZIPは1個につき元データ20GiB・5000ファイルまでです。空き容量も確認します。
通常の台帳への添付上限10MiBは従来どおりなので、より大きいデータはZIP登録を使います。
モデルフォルダーの `.git`、`.venv`、`__pycache__`、`.pytest_cache` は含めません。リンクを含む資料は拒否します。
指定フォルダー内の他のファイルもまとめて対象になるので、共有したい資料専用のフォルダーを選んでください。
検証には全ファイルを読む時間がかかります。処理中に閉じると中断完了を待って終了確認を表示します。

## 通信・容量・互換性

- 自動共有は起動中に通常約60秒ごと、1回に最大3件です。未保存入力は送信しません。オフラインでもPC内の保存は続けられます。
- 900KB超の添付があり、ZIPの場所が未設定ならその記録は送信保留です。他の共有可能な記録を先に送ります。
- 同じ資料を通信失敗後に再送する場合は、検証済みの既存ZIPを再利用します。毎回新しいZIPや全台帳のバックアップは作りません。
- 受信の直前復旧用に、台帳だけの `.autosync/ledger-before-import.json` を1個更新します。既存の手動バックアップを変更・削除しません。
- 同じIDの後編集は競合として保持します。削除は他PC・GitHubに伝播しません。修正結果は新規記録として保存します。
- 1リポジトリの一覧は最大100プロジェクト、各プロジェクトのGitHub実験一覧は1000件未満までです。上限時は停止して表示します。無料サービスの将来の提供・無制限容量を保証するものではありません。
- 有料プラン・課金への切替を行う処理はありません。共有フォルダー自体の容量は班が用意した保存先に依存します。
- ZIP利用の記録は新しい自動共有で取得します。従来の手動GitHub取得では説明して停止します。ZIP添付を復元するまでは、従来の品質点検で添付不足と表示されます。
- 年度・班付きの共有ファイルを読むPCも、このGUI版へ更新してください。更新前の厳格な読込処理は追加項目を拒否します。
- INO固定の旧自動共有試作設定は、今回の版では共有先を再指定するまでOFFです。意図しない送信先を引き継ぎません。

ローカルの設定は `projects/<ID>/.autosync/settings.json`、大きい添付の配送情報は `.autosync/transports/<記録ID>.json` です。
台帳の記録そのものを配送情報で書き換えないため、既存の保存内容やIDを保てます。
