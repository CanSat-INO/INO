# CanSat Module Test Lab v10：Main・CAM・Drive C++個別試験

## 何ができるか
- PCで実行できるC++制御判断ファイルをMain・CAM・Drive別々に指定し、それぞれ独立にg++でコンパイルする。
- 着地イベント、走行指令、撮影指令、停止指令について応答（許可1、拒否0、未対応-1）を取得する。
- Main未着地時の走行許可、未対応指令への応答を追加チェックとして一覧表示する。
- 3モジュール一括実行時に判断を既存の仮想CAN通信に反映し、通信欠落／C++拒否を区別する。
- CSVに個別の判断・仮想イベント・ソースコードSHA256を記録する。
- 一括試験の結果をv9の「統合実験結果」から既存台帳に保存できる。
- 既存の140件の自動テストはそのまま維持し、新しい試験を追加する。

## 重要：この試験で検証できないもの
この機能は実際のArduino/ESP32-S3ファームウェアをコンパイル・実行しません。
CANの物理層、実際のセンサー・カメラ・モーター、割り込み・RTOS・タイミング保証を検証するものではありません。
プログラムは **隔離（サンドボックス化）されずPCで実行** されるため、本人・チームが内容を確認した信頼できるC++だけを読み込んでください。

## 本番コードの移行方法
- ESP32/Arduino固有の処理と、制御判断ロジックを分離する。
- PCでコンパイルできる判断ロジックを1つの.cppに置き、`cpp_module/controller_contract.h`の関数を実装する。
- 1つの.cppは **1つのモジュール** を担当し、担当外の指令には-1を返す。
- 公開C関数は `extern "C" int cansat_allow_command(int module, int command, int landed)`。
- 返り値は 1（許可）、0（拒否）、-1（未対応）を使用。標準出力にデバッグ文を出さない。
- デフォルト例 `cpp_module/example_main_v10.cpp` / `example_cam_v10.cpp` / `example_drive_v10.cpp` から始める。
- CAMの拒否例 `example_cam_deny_v10.cpp` に切り替えると仮想CAN中のC++拒否が再現できる。
- C++ソース内のローカルヘッダーはそのソースと同じディレクトリからインクルードできるが、多数の.cppをリンクするビルドシステムや外部ライブラリの自動解析はしない。

## 検証手順
1. ホーム／☰から「Main・CAM・Drive C++個別試験」を選択。
2. デフォルト3ファイルと「正常なモジュール連携」で一括試験 → 成功。
3. CAMのみ `example_cam_deny_v10.cpp` に変えて実行 → CAMのC++拒否、最終評価が失敗。
4. 正常な3ファイルに戻し、シナリオを「Drive走行指令の欠落」に変更 → 欠落／タイムアウトを確認。
5. 「試験対象」を「Mainのみ個別試験」に変更 → 着地1/0、未対応指令チェックが表示される。個別試験では仮想CANを実行しない。
6. 「結果CSV出力」を保存して内容を確認。
7. 一括試験を再実行して「統合実験結果」で保存対象「Main・CAM・Drive C++個別試験」を選び、台帳へ保存。
8. GUI正常終了と、自動テスト合格を確認。

## インストール
ブランチ：`feature/real-cpp-integration`、`module_test_lab`以下がGitクリーンな状態で実行。
ZIPを展開して `python3 install_individual_cpp.py` を実行する。依存：既存v9、g++、PySide6。
バックアップ：`~/cansat_module_lab_backups/v10_*/`。
インストーラは GitのコミットやPush、実験データの上書き・削除を行わない。
