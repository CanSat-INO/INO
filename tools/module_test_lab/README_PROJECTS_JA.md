# CanSat Simulation：プロジェクト別トップと保存

外観修正v2：スクロール領域の背景を明示的に濃紺で塗り、上部ヘッダーを縮小しました。プロジェクトが未登録の場合は空の一覧を隠して案内を表示します。更新済みのプログラムへ同じ更新を再実行しても、変更せず終了するインストーラーにしています。

`cansat-lab` は最初に「CanSat Simulation」のプロジェクト作成・選択画面を表示します。既存の機能画面はそのまま利用し、濃紺の操作パネルと読みやすい入力・表へ統一します。グラフは既存の描画処理を維持し、明るいキャンバスで信号と軸を読み取れます。

## 基本操作

1. トップでプロジェクト名・担当者/チーム・目的を入力して「作成して開く」。作成済みのプロジェクトは一覧から再開できます。
2. プロジェクト概要の「＋ 新しい実験」でv20を開き、実験名・担当者・使用機器・コード版を入力します。
3. CSV確認、解析、実験記録票へ進みます。v16で「実験記録を保存」を押すと、選択中のプロジェクトに台帳と添付が保存されます。
4. 作業途中はv20のJSONを保存します。新規プロジェクトでは `sessions/` が初期保存先です。
5. 「ホーム」で現在のプロジェクト概要に戻ります。「機能一覧」や「すべての機能・検索」から従来の全機能を利用できます。従来のセンサー・記録・ミッション・比較の4入口も維持しています。
6. 「プロジェクト切替」を押すと従来の終了確認が表示されます。未保存入力があればキャンセルして保存してください。作業画面の終了後、プロジェクト選択に戻ります。

## 保存先

```text
~/cansat_module_lab_data/
  records.json                 従来の未分類台帳（移動しません）
  attachments/                 従来の添付（移動しません）
  projects/<32桁のID>/
    project.json               名前・担当・目的
    records.json               このプロジェクトの台帳
    attachments/               このプロジェクトの添付
    sessions/                  作業JSONの初期保存先
    exports/                   解析・比較結果等の初期保存先
    v12_experiment_batches/    このプロジェクトの一括実験履歴
  project_backups/<ID>/        新規プロジェクトのバックアップ
  project_trash/<ID>/          新規プロジェクトの削除退避ZIP
```

プロジェクト名をフォルダー名には使いません。重複した名前でも異なるIDを持ちます。プロジェクトの作業画面を別プロセスで開き、起動前に保存先を固定します。既存モジュールの保存先定数やバックグラウンド処理が別プロジェクトのものを持ち越さないための構成です。

トップを表示するだけでは従来台帳を開きません。過去の記録は「既存の実験を開く（未分類）」から利用します。新規プロジェクトへ自動移行しません。プログラムを復元しても、作成したプロジェクトデータは残します。

## 共有と互換性

- 既存の記録形式・手動保存・合否判定・CSV解析・ZIP検証の処理は維持します。
- 新規記録に `project_id` を追加します。別プロジェクトの記録ZIP・削除退避ZIP・新形式の作業JSONを、そのまま別プロジェクトへ取り込むことは拒否します。
- IDが付いていない従来の記録ZIPは、利用者が選んだプロジェクトに手動で取り込めます。ファイルを取り込む前に対象プロジェクトを確認してください。
- 旧作業JSONは読み込めます。IDのない旧JSONは現在のプロジェクトで開く扱いです。新たに保存すると対象IDが付きます。
- GitHub共有は従来どおり利用者の手動操作です。取得時は、選択中のプロジェクトとIDが一致する記録のみを取得します。未分類ではIDが付いていない記録のみ取得します。開発・更新処理からGitHubへ送信しません。
- 記録ZIPやGitHubの実験記録共有は、プロジェクト自体の新規登録やメタデータ配布を行いません。他PCで同じプロジェクトを使う場合は `projects/<ID>/` フォルダーを同じ場所へコピーし、トップを再読込します。同じIDのフォルダーを上書きしないでください。
- 添付・台帳の削除退避は当該IDの領域を使います。既存の削除退避・バックアップは変更しません。
- 解析結果の保存ダイアログでは `exports/` を初期表示します。利用者が別の保存先を手動で選ぶこともできます。

## 確認方法

```bash
cd ~/INO-module-lab/tools/module_test_lab
python3 -m unittest discover -s tests -p test_project_store.py -v
~/cansat_gui_venv/bin/python -m unittest discover -s tests -p test_project_gui.py -v
~/cansat_gui_venv/bin/python -m unittest discover -s tests -p test_v20_workspace_gui.py -v
python3 -m pytest -q tests/test_v20_workflow_core.py tests/test_v20_workspace_core.py tests/test_v15_sensor_core.py tests/test_v16_experiment_core.py tests/test_v19_compare_core.py tests/test_v21_quality_core.py
```

新規の自動試験は一時HOMEを使用します。GUI試験は実際のQt部品をオフスクリーンで操作するもので、日本語IMEや実機の試験ではありません。大型ソフトやデータベースの追加導入は不要です。
