# Gazebo カメラ試験とModule Test Lab

## 起動

INO直下の **start-module-test-lab.bat** を開く。
ホーム／機能一覧から **Gazebo カメラ試験** を選ぶ。

初回はUbuntu内でリポジトリ直下から以下を実行する。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install PySide6
# ROS側の依存パッケージが未導入の場合のみ
bash ros2_ws/src/ino_camera_sim/scripts/setup.sh
```

Ubuntuから直接起動する場合：

```sh
.venv/bin/python tools/module_test_lab/app.py
```

## 操作

1. 「初期設定を読込」を押す。以前に保存したJSON/YAMLも読み込める。
2. カメラの位置・画角・解像度・左右間隔、撮影方式などを設定する。
3. 手動観察は「Gazebo・RVizを起動」。走行にはcamera-teleop.batを使う。
4. 自動評価は「設定した経路で試験・結果保存」。読込設定のtest項目にある
   速度・距離・旋回・繰り返し回数を使い、画像・推定軌跡・評価結果を保存する。
   自動評価は画面なしのGazeboサーバーで実行するが、描画環境は必要。
   「自動試験の上限 (分)」は既定10分。WSLの描画が遅い場合は増やせる。
   上限に達した試験は成功扱いにせず、未完了として結果に残す。
5. 終了後は結果一覧を選び「選択結果を開く」。設定、左右画像、軌跡図、
   result.json、地図DBを確認できる。「比較CSV保存」で一覧を出力できる。
6. 手動観察を終了するときは「停止」。Test Labを閉じる際は終了確認が表示され、「はい」で停止処理を待って終了する。「いいえ」では試験を続ける。

変更は実行ごとの設定スナップショットへ保存し、シミュレーションの既定設定を上書きしない。
一覧は既存のカメラ試験ログも読み込む。手動観察には真値比較のresult.jsonがないため、
一覧の評価対象にはしない。手動観察中は撮影ペア・軌跡・点群の状況を表示する。

## 結果の読み方

「試験完了」と「SLAM追跡が十分か」は別。
一覧では有効姿勢10件以上、有効率80%以上、最後の姿勢が3秒以内という
移植元の目安を満たすか併記する。実機成功率を表すものではない。
CSVにはローカルフォルダーの絶対パスを入れない。

## 接続の範囲

Test LabはPySide6のvenv、ROS/GazeboはUbuntuのシステムPythonで動く。
ROSのライブラリをTest Labにimportせず、起動プロセスとJSONの設定・結果で接続する。
既存v11/v12の仮想CAN設定とは独立しており、設定や結果を黙って混ぜない。
実験台帳・ZIP共有・GitHub送信への自動登録は行わない。
本番ファームウェアの実行や、ROS画像を仮想CANへ送る連動は今回の対象外。

## 接続の動作確認

- 既存機能を含む204テストと、新しい画面の停止処理4テストを確認。
- 実際のQt画面からGazeboを起動し、撮影ペア・SLAM軌跡・点群を受信。
- Test Lab終了時にカメラ処理を停止する経路を確認。
- 自動試験は約8cmの走行で撮影124ペア・有効姿勢121件を保存し、
  同じ実行フォルダーから結果一覧へ読み込めることを確認。
- GUIロジックはoffscreen描画で検証。Windowsから通常のGazebo/RViz画面を
  操作する一連の手動確認は別途必要。
