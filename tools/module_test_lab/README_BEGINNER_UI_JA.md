# CanSat Simulation：トップ画面の使い方

トップ画面を、普段使う「開く」「参加」と、立ち上げ時に使う「作る」に整理しました。
濃紺の外観とCanSat Simulationのタイトルを維持し、横長の画面でも入力欄が伸びすぎないよう中央の幅を最大1080pxにしています。

## 普段使う人

トップの「このPCのプロジェクト」から選び「選択したプロジェクトを開く」を押します。
登録が1個なら自動で選択します。複数あるときは自分の班・年度を確認して選びます。
現在のプロジェクトを開いている間は、従来の実験ワークスペースと4つの機能入口を利用できます。

## 初めて参加するメンバー

1. 「班のプロジェクトに参加」を押します。
2. 案内されたGitHubリポジトリのリンクを貼り「プロジェクトを探す」を押します。例：`https://github.com/CanSat-INO/INO`。
3. 見つかった一覧から班のプロジェクトを選択し「選択した共有プロジェクトに参加して開く」を押します。
4. 共有先・ID・保存済み記録の送受信について確認し、参加します。

検索だけでは実験データの送信・参加登録は始まりません。検索した共有先はこのPCの一覧設定に記憶します。
一覧の自動更新はチェックを外せば停止できます。設定済みの自動更新は次回起動にも引き継ぎます。
班から指定されたブランチが `main` 以外なら「詳細設定（通常は変更不要）」を開いて変更してから検索します。
前に指定したブランチは維持します。リンク先が非公開であること、UbuntuのGitHubログインと権限が必要な点は従来どおりです。
共有プロジェクトが0件の場合は、作成した人にプロジェクトのホームで自動共有をONにしてもらってください。

共有ファイルを渡された場合は、同じ参加画面の「受け取ったプロジェクト共有ファイルから参加…」を使います。
このファイルによる登録だけでは実験データは同期されません。ホームの共有設定は従来どおり利用できます。

## 新しい年度・班を作る人

「＋ 新しいプロジェクトを作る」で入力欄を開きます。既存の班に参加する場合は新規作成しません。
プロジェクト名・年度・班を入力し「作成して開く」。担当者と目的は任意です。
作成と参加を切り替えても、作成途中の入力は保持します。入力欄を開く・閉じる操作ではデータフォルダーを作りません。
実験の保存先・プロジェクトID・記録形式・共有先・ZIPの扱いは [Git・ZIP共有の説明](README_GIT_ZIP_JA.md) と同じです。

## 従来の機能

「共有・従来のデータを開く…」に、プロジェクト共有ファイルの作成と、従来の未分類の実験への入口をまとめました。
共有ファイルを作成する場合は、先に一覧で対象のプロジェクトを選んでください。
この変更で既存の台帳・添付・バックアップやファームウェアを移動・削除しません。

## 今回の範囲

今回はトップ画面と参加の案内を改善しました。
実験画面を「次へ」で進む形式への変更、下書きと結果の保存ボタン名の整理、保存・共有状態の常時表示の統一は今回に含めていません。
初期設定担当者用の権限・メンバー承認を追加するものではありません。閲覧や書込みの権限はGitHubと共有フォルダー側で管理します。
