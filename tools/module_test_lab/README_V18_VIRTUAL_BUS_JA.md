# v18 — Main・CAM・Drive 仮想メッセージ連携検証

本機能は **オフラインのダミーデータと仮想メッセージ** に限定した、インターフェース検討用の小規模テストです。ROS 2/Gazebo、ESP32-S3実コード、実際のCAN/TWELITE、ネットワーク、モーター・センサー、地上局には接続しません。

## 操作

1. 通常通り `cansat-lab` で起動する。
2. ホームから「Main・CAM・Drive 仮想通信検証（v18）」を開く。
3. 「正常な仮想通信」で「仮想通信を試験」を押す。
4. 遅延・欠損・重複・期限切れのケースを選び、それぞれログを確認する。
5. 必要ならCSV、JSONでシミュレーションの条件と結果を保存する。

## 最初に試すシナリオ（既定値）

| シナリオ | 期待する模擬結果 |
|---|---|
| 正常な仮想通信 | PASS：指令・応答・CAM検出通知を受信 |
| Drive応答（ACK）欠損 | STOPPED：DriveのACK期限超過 |
| CAM検出通知の欠損 | STOPPED：CAM通知の期限超過 |
| Drive指令の重複受信 | PASS：重複を1件除外 |
| Drive応答の大幅遅延 | STOPPED：ACK期限超過 |
| 古いCAM検出通知 | STOPPED：古いメッセージを拒否し通知期限超過 |
| 緊急停止メッセージ | STOPPED：仮想緊急停止入力に応答（実モーター停止未検証） |

## モデルについて

この画面の Main・CAM・Drive は **仮のロジックを持つ3つの名前付きノード** で、本物の制御用ファームウェアではありません。

仮ルール:
- Main → Drive `DRIVE_CMD` に対して Drive → Main `DRIVE_ACK` を返す。
- CAM → Main `CAM_TARGET` を送信する。
- CAM → Main `EMERGENCY` を送信すると、Main は仮想STOP要求を出す。ただし実機を停止したわけではない。
- ACKが期限内に届かなければ失敗と判定する。
- メッセージの重複番号は再実行しない（仮想実装）。
- 古いCAMメッセージは受信を拒否する。

固定のイベント時刻は **説明用** であり、v17の物理モデルや実験ログの結果ではありません。v17の段階的な状態遷移シミュレーションと、v18の通信モデルは現時点で独立しています。実コードを使った検証はv14.1のホスト検証から別途進めます。

**開発方針**：将来コード担当者が各モジュールの仕様を決めたら、通信の種類・ID・タイムアウト・再送規則などを決め直してから実機ログとの整合性を確認してください。実機による安全性・信頼性を保証するものではありません。
