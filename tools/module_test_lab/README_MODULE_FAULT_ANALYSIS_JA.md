# CanSat Module Test Lab v8.3 — 仮想モジュール異常の時系列分析

## 目的

v8.1の仮想CANログとv8.2のPC用C++判断結果を再利用し、**最初に記録された異常**と、その後に**観測されたタイムアウト・FAULT・停止指令・最終評価**を分けて表示します。

これは新たな通信エミュレーターを作る機能ではありません。既存ログの事象を時系列に関連付けて、ソフト班が調査しやすくするものです。

## 使い方

1. GUI の `異常分析` タブを選びます。
2. `Drive走行指令の欠落` を選び、サンプルC++のまま `原因を分析` をクリックします。
3. `発端` の欠落 → `波及` のタイムアウト・FAULT → `停止指令` → `最終結果` を確認します。
4. 比較として `正常なモジュール連携` を実行すると `異常なし` と表示されます。
5. `cpp_module/example_reject_cam.cpp` を選択して正常シナリオを実行すると、CAMの `C++拒否` を起点に分析します。
6. `分析ログCSV出力` で全通信イベントと関連する分析段階を保存できます。

### 異常の種類と読み方

- **C++拒否**：PC用C++の判断が指令を拒否しました。ソースの条件式などを確認する出発点です。
- **欠落**：仮想故障設定によりメッセージが配送されませんでした。
- **タイムアウト**：決めた期限内にACKが届かなかった事実です。原因は欠落とは限らず遅延なども考えられます。
- **異常**：仮想Main/モジュールがFAULTへ移るなどのイベントです。多くの場合、それ以前の事象の影響です。
- **停止指令**：MainがSTOPを送信した記録です。**Driveが実際に停止した証拠ではありません。**
- **未判定（着地入力なし）**：故障とみなさず、指令を出さない想定動作として扱います。

「発端」は**最初に記録された異常イベント**です。根本原因を確定するものではありません。ログに現れない状態や本番CANの不具合は評価できません。

## 対応範囲・制限

- v1〜v8.2 の機能は変更しません（`app.py` にタブを追加）。
- 仮想通信、仮想状態遷移、PC上で実行する信頼できるC++コードを分析対象とします。
- **ESP32-S3実機のプログラムや物理CANの故障診断ではありません。**
- v8.2と同様、C++の4つの判断は事前に取得し、時刻ごとの内部状態更新には未対応です。
- C++コンパイル・実行は任意コードをPCで動かします。信頼できるチーム内のソースのみ選択してください。
- CSVは時系列通信ログであり、ダッシュボードのIMUなどのセンサープロットとは別形式です。
