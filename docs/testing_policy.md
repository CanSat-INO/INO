# 試験方針

単体 → モジュール → 結合 → システム → 大会想定の順で確認する。要求・重要な異常系・共通仕様との整合、担当による説明、レビュー、試験記録の更新を完了条件とする。

異常系は仮想入力・ダミー出力から始める。再起動、CAN/TWELITE/Wi-Fi途絶、センサー異常・誤判定、機構異常、片側画像欠損、VO失敗、スタック、地上局/UI停止、NVS書き込み中の電断、容量不足、古い・重複した指令、再起動ループを確認する。

Fullは寸法・距離誤差、MAE/RMSE、再現性、欠損率、姿勢・位置の誤差、処理時間から適切な指標を選び、実測と比較する。Extraは実機の登坂・段差・形状・旋回性能を評価に反映する。合格値は担当間で決める。

大会前は安定化を優先し、確認済みのコード版、バイナリ、設定、校正と復旧手順を保管する。試験は[試験記録](templates/test_record.md)で残す。
